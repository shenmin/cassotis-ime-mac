**[Website: www.yanquan.org](https://www.yanquan.org)** | English | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Windows version](https://github.com/shenmin/cassotis-ime) | [Linux version](https://github.com/shenmin/cassotis-ime-linux)

Cassotis IME for macOS (言泉输入法 macOS 版) is an experimental Chinese Pinyin input method for macOS on Apple silicon. A native InputMethodKit / AppKit frontend talks to a separate engine process written in Free Pascal, ported from [Cassotis IME for Windows](https://github.com/shenmin/cassotis-ime), with dictionaries generated by [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon). Candidate ranking runs entirely on the local CPU, around a single character-level language model trained by the project. It shows no ads, bundles no software and uploads nothing you type: dictionaries, settings and what it learns stay on the Mac.

Version 2.7.0 (build 8) follows Cassotis IME and Cassotis Lexicon v2.7.0 and runs on Apple silicon with macOS 14 or later. Download the [v2.7.0 installer](https://github.com/shenmin/cassotis-ime-mac/releases/download/v2.7.0/cassotis-ime-macos-2.7.0-arm64-installer-signed.dmg) or read the [release notes](https://github.com/shenmin/cassotis-ime-mac/releases/tag/v2.7.0). The [website](https://www.yanquan.org/mac) has an overview, [COMPATIBILITY.md](COMPATIBILITY.md) the tested environments and known limitations, and the [version history](#version-history) below what each release brought.

The project focus is:
- keep the macOS engine aligned with each Windows release and verify the alignment on the same benchmarks,
- integrate natively with macOS text input through public InputMethodKit and AppKit interfaces, without Accessibility or Input Monitoring permission,
- ship a signed and notarized installer that runs without network access or a GPU.

## Name Origin
The English name **Cassotis** comes from the sacred spring inside the Temple of Delphi. Before delivering oracles, the priestess Pythia was said to drink from this spring to enter a prophetic state. The spring was regarded as the true source of prophecy and inspiration, where oracles were born, which resonates with the path from Delphi to human language.

The Chinese name **言泉** (Yanquan, "Spring of Words") matches Cassotis as a prophetic spring, while also carrying the meaning of **言如泉涌** ("words flowing like a spring"), reflecting our expectation of a fluent and intelligent input experience.

## Features
- **Native input method.** An InputMethodKit input source with an AppKit candidate window that never takes input focus from the application. Composition, partial selection and commitment work in native text fields, WebKit, Chrome, Electron and Terminal; secure password fields keep the system's behavior.
- **Candidate window.** Two rows by default: up to nine numbered candidates without wrapping, and a Tab completion row that always stays, with the logo and version. Paging can expand the window to three candidate rows; numbers and Space select from the active row and the mouse from any visible row. All characters for a complete syllable remain reachable by paging, including readings with more than 256 characters. A small red × beside a learned word removes it. Eight color options, fonts from 12 to 32 points (14 by default) and live previews. By default the window stays at the start of the composition while you type; Appearance can make it follow the caret instead. Optionally, `;` and `'` pick the second and third candidate while Pinyin is being typed (off by default; in Double Pinyin a `;` that types a final takes priority). A right click on the window opens the menu for switching modes, Settings and About, and the composition stays.
- **Chinese/English mode.** A bare Shift switches modes, and a short bubble beside the caret shows the logo with 中 or 英. The bubble can be turned off in Appearance. It also shows the mode when switching to Cassotis, and reminds you of English mode on entering a text field. Caps Lock can optionally replace Shift; this binding currently does not distinguish a short tap from a long hold (see [configuration](CONFIGURATION.md)). Each application remembers its own mode by default. A modifier-only shortcut is cancelled when another key or a click happened while the modifier was held; the frontend compares system-wide event counts for this and reads no key contents.
- **English recognition.** In Chinese full-Pinyin, half-width mode, letters that are an English word or name (`pro`, `markdown`, `Effie`), that are typed with a capital, or that were committed as letters before appear before the numbered candidates, keeping their capitalization. When the input has no Chinese reading as a whole they are selected and Space commits them as typed; when it has one (`bug`, `mac`), the language model weighs the letters against it with the preceding text. Arrow keys and the mouse move between the letters and the Chinese candidates, Chinese selection numbers stay unchanged, and choosing the letters is remembered without adding a user word. Enabled by default and optional in Settings; Double Pinyin keeps its normal behavior.
- **One-key completion.** Exactly one trusted continuation is shown in the Tab row and accepted with the configured key. Exact completions from the user and base dictionaries and offline-vetted strong-transition completions appear at once; the language model then reranks them in the background, using the text before the cursor when there is any. In a long sentence it finishes the current word or continues with the next phrase, and shows nothing when its confidence is insufficient. Predictions use the theme's accent color; a plain join of the words already typed uses the ordinary text color. Classical verses can complete from their opening syllables; entering a full line can offer the next line, such as 春眠不觉晓，处处闻啼鸟.
- **Long sentences.** Lexicon-constrained path search builds complete candidates (for example `womenjintian` → `我们今天`) while keeping prefix candidates for partial commitment. The language model chooses among the complete candidates. In simplified and traditional Chinese, with full or Double Pinyin, it also corrects small homophone errors in the chosen sentence against the typed Pinyin and the text before the input.
- **Short words.** The language model resolves competing exact candidates using prior text and general-text word frequencies. Without context, a much rarer word cannot displace a common first choice, and a first choice that everyday conversation uses far more often keeps its place. After preceding text, the characters of a single syllable are also ordered by the language model.
- **Short phrases.** In simplified or traditional Chinese, an input of three to five syllables that the dictionary does not contain (for example `jiuguize` → `旧规则`) gets whole phrases put together from dictionary words. The language model picks one, using the text before the cursor when there is any, and corrects its homophones against the typed Pinyin; when the choice is close, up to two more whole phrases follow the first.
- **Pinyin schemes.** Full Pinyin and seven selectable Double Pinyin schemes (Microsoft, Xiaohe, Ziranma, Sogou, Ziguang, Pinyin Jiajia, and Zhineng ABC) share the same candidate ranking and user-learning data. Fuzzy Pinyin is configurable, initial-letter abbreviations are supported (for example `jt` → `今天`), and `v` types ü (`lv`, `nv`; `lue`/`nue` and `jv`/`qv`/`xv` are accepted too).
- **Dictionaries and learning.** Separate simplified and traditional base dictionaries and a user dictionary. Learned words are shown in the active script without being learned again. Specialist vocabulary appears only for its exact input. Letters that no syllable explains are marked in red without changing the input. Word frequencies exported by another input method can be imported in Advanced; see the [frequency import guide (Chinese)](CONFIGURATION.md#输入频次导入).
- **Quick input.** `ufh` symbols, `uxh` numbered markers, `usx` mathematical symbols, `urq` / `usj` the current date and time, and more; `i123.45` or `v123.45` offers Chinese numbers and uppercase currency amounts, selected with the displayed `a/b/c/d` keys while digits keep entering the number. Double Pinyin enters these modes with Shift+U/I/V. See the [quick-input guide (Chinese)](QUICK_INPUT.md).
- **Chinese punctuation.** With Chinese punctuation and half-width input, a full stop typed right after digits becomes a decimal point, and the symbols that stay as typed can be edited in Settings, set to the Markdown preset or to standard Chinese punctuation. The default Markdown preset keeps ``-#*+_=`~[]<>|@``; commas, full stops, parentheses and quotation marks stay Chinese, and the backslash gives the enumeration comma `、`.
- **Custom phrases.** Define ordered letter shortcuts and commit literal, multiline text with Tab, without changing numbered candidates or Space. Import and export JSON compatible with Windows. Fill in the shortcut and text, then click **添加短语** (Add Phrase); editing an existing entry uses **保存修改** (Save Changes) or **取消编辑** (Cancel Edit).
- **Settings.** A sidebar settings window that saves every confirmed change at once, with direct shortcut recording and font-name completion. Logging is off by default.
- **Local by design.** No network and no GPU. Keys typed while the engine starts are kept and converted once it is ready; while the language model is loading or unavailable, candidates are ranked without it.

## What's new in 2.7.0

- **Zhineng ABC Double Pinyin.** All seven layouts can use short-word ranking, phrase generation, sentence correction and Tab continuation. These model paths also work in traditional Chinese.
- **Characters follow the context.** With preceding text, homophone characters are ranked by model probability and a small usage-frequency contribution. Without context, common characters retain their order; learned choices stay protected.
- **Better sentence and phrase choices.** A corrected sentence can receive a second correction pass. Phrases ending in 没 are scored as questions, with additional guards against rare completions and literary words displacing everyday expressions.
- **More selection options.** Optionally use semicolon and single quote for the second and third candidates; disabled by default, with Double Pinyin finals taking priority. Right-click the candidate window to switch modes or open Settings and About.
- **A steadier candidate window.** It stays at the beginning of the current composition by default. Appearance can switch it to follow the caret, with changes taking effect immediately.
- **Updated model and dictionaries.** New v2.7.0 model weights, ranking parameters and lexical data add conversation-frequency protection and Taiwan traditional-form corrections. Only one neural model is distributed.

## Download and Install
- **Download.** Get `cassotis-ime-macos-<version>-arm64-installer-signed.dmg` from the [Releases](https://github.com/shenmin/cassotis-ime-mac/releases) page. The disk image is about 340 MB and includes the simplified and traditional base dictionaries and the language model. Release images are signed with the Sunisoft Limited Developer ID and notarized by Apple.
- **Requirements.** A Mac with Apple silicon and macOS 14 or later. No Terminal commands, compiler, Python installation, network or GPU are needed.
- **Install.** Open the disk image, double-click **言泉输入法安装器** (Cassotis IME Installer) and click **安装** (Install). The installer asks macOS to enable the input source; click **Allow** if a confirmation appears. Once **安装完成** (Installation Complete) appears, select **言泉输入法** from the input menu in the menu bar and type `nihao` followed by Space to enter “你好”. If enabling is still pending, click **重试启用** (Retry Enablement), or **打开键盘设置** (Open Keyboard Settings) to add the input source by hand.
- **macOS 27.** The system may open Keyboard Settings without a confirmation. Add **言泉输入法** under **Text Input → Edit → + → Chinese, Simplified**, then return to the installer; it checks that the input source is enabled.
- **Upgrade.** Run the installer of the new version over the installed one. It keeps the settings and learned words, shows its progress, and offers the log and a retry when something fails.
- **Uninstall.** Remove the input source in System Settings first, then use the uninstall option of the installer. Settings and learned words are kept.

## Architecture
- `src/macos`: InputMethodKit input controller and AppKit candidate window, mode bubble and settings window (Objective-C++).
- `src/service`, `src/ipc`: the engine process service and its Unix-socket protocol.
- `src/engine`, `src/dictionary`: Pinyin parsing, candidate generation, ranking and user learning, ported from Windows.
- `src/host`: language-model hosting; `src/host/native` holds the C++ bridge to ONNX Runtime and the attention operator.
- `src/common`: configuration, types and platform adaptation.
- `src/installer`: the graphical installer.
- `tools/dictionary`, `tools/control`: the dictionary importer and the input-source control tool.
- `data`: the language model (`data/models/char_lm`, stored as numbered parts), its checksums and the lexicon input hashes.
- `scripts`, `resources`: build, installation and packaging scripts; icons and bundle resources.
- `third_party`: ONNX Runtime headers and version, and the licenses and notices of bundled components.

See the [architecture document (Chinese)](docs/ARCHITECTURE.md) for the processes, the protocol and recovery.

## Runtime Files
- `Cassotis.app/Contents/MacOS/Cassotis`: the input-method frontend; macOS starts it for the input source.
- `Cassotis.app/Contents/MacOS/cassotis-engine`: the engine process; it loads the dictionaries and the language model. The frontend starts it with `--serve` and talks to it over a private Unix socket.
- `Cassotis.app/Contents/Frameworks/libcassotis_ort.dylib` and `libonnxruntime.1.20.1.dylib`: the language-model bridge and its runtime; only the engine process loads them.
- `Cassotis.app/Contents/Resources/models/char_lm`: the language model, its vocabulary, Pinyin readings and manifest.
- `Cassotis.app/Contents/Resources/dictionaries`: the simplified and traditional base dictionaries (`dict_sc.db`, `dict_tc.db`).

Without the engine process no input is converted. When a request fails or times out, the frontend commits the last visible composition, passes the key on to the application and starts the engine again. Without the model files the input method still works and ranks candidates without the language model.

## Build and Install (Quick Start)
Prerequisites: a Mac with Apple silicon, Free Pascal 3.2.2, the Xcode command-line tools and Python 3.11 or later. Lazarus/LCL is not required. Obtain the generated artifacts of [Cassotis Lexicon v2.7.0](https://github.com/shenmin/cassotis-lexicon) and point `CASSOTIS_LEXICON_ROOT` to that checkout (`/path/to/...` is a placeholder):

```sh
./scripts/check_environment.sh
export CASSOTIS_LEXICON_ROOT="/path/to/cassotis-lexicon"
./build_all.sh
./install.sh
```

The application is built at `build/arm64/Cassotis.app` and installed for the current user in `~/Library/Input Methods/Cassotis.app`; run the scripts without `sudo`. Add 言泉输入法 under System Settings → Keyboard → Text Input, then select it from the input menu. If the input-source list does not refresh, log out and log back in.

`build_all.sh` builds the language-model bridge, the engine, both dictionaries, the frontend and the installer, and joins the numbered parts in `data/models/char_lm` into the `char_lm.onnx` the application carries, after checking their SHA-256 values. The first build downloads the official ONNX Runtime 1.20.1 arm64 package and checks its pinned hash. `./rebuild_all.sh` cleans and rebuilds everything, `./uninstall.sh` removes the input method and keeps the learned words, and `./scripts/package.sh` builds the installer disk image. See [BUILD.md (Chinese)](BUILD.md) for the options, packaging and signing.

## Dictionary Workflow
The base dictionaries are the schema-24 SQLite databases of [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon), built from the 30 generated files under its `data/generated/`:
- the word lists `dict_unihan_sc.txt`, `dict_unihan_tc.txt`, `dict_clean_sc.txt` and `dict_clean_tc.txt` (`pinyin<TAB>text<TAB>weight`),
- the tables trained from corpora in the same directory: word-transition priors, completion priors, general-text and conversational word frequencies, and the short-word promotion table.

The build checks each file against [data/lexicon-inputs.json](data/lexicon-inputs.json) and imports them into `dict_sc.db` and `dict_tc.db`, which go into the application bundle. The v2.7.0 dictionaries hold 264,167 simplified and 267,265 traditional reading records, single characters included. The user dictionary, the engine settings and learned data are in `~/Library/Application Support/CassotisIME/`; replacing the application never overwrites them.

## Models and Ranking
The language model and the compact ranking units are those of Cassotis IME for Windows v2.7.0: the same model bytes and the same compiled parameters.

### The language model
- **One model for every input path.** A character-level autoregressive language model of about 150 million parameters (11 layers, 1,024 dimensions, a 12,017-character vocabulary, 8-bit quantized), trained by the project. It scores complete long-sentence candidates and corrects the chosen sentence against the typed syllables, chooses among short words and orders single characters after a context, composes phrases outside the dictionary, weighs typed letters against a Chinese reading, reranks one-key completions, and proposes and selects long-sentence Tab continuations. The separate models of earlier releases are no longer in the application.
- **Training data.** Independent Chinese corpora (general text and fiction), both as a plain language model and conditioned on Pinyin. Since 2.7.0 it has also learned everyday conversation: its training continued on the tenth of the public LCCC dialogue corpus closest to everyday chat, and the result was averaged with the previous model, so that fiction and general text keep their scores. No benchmark case is in any training data.
- **Scores that do not depend on the call.** The model is quantized with fixed activation ranges and computes attention with an operator of its own, whose Apple-silicon NEON kernel keeps the summation order of the Windows kernel. A text gets the same scores however it is batched and whatever was computed before, so a long sentence typed key by key gets the same candidates as the same Pinyin entered at once.

### Decisions around the model
- Six small gradient-boosted policies turn the language model's scores into decisions: the long-sentence choice, the short-word choice without a context, the short-word choice with a context and a finer check of it, one-key completion, and Tab continuation. They are fit on Windows engine traces over independent corpora, refit whenever the model changes, and compiled into the engine with the same parameters as on Windows.
- Three compact structural rankers keep long-sentence search and the pool of complete candidates manageable.
- Statistical tables from the lexicon add what the model does not see by itself: word transitions, completion priors, a short-word promotion table precomputed for the dictionary, and how often general text and everyday conversation use each word.

### How candidates are ranked
For traditional input, the model scores the corresponding simplified text and the engine converts generated completions to Taiwan traditional forms. Foreground selection and background completion share the same model.

- **Long sentences.** Lexicon-constrained search builds complete candidates; two rankers decide which paths survive pruning and a third orders the pool of complete candidates. The language model scores the leading candidates and the long-sentence policy picks the first and the second. For full or Double Pinyin in either script, the model then makes up to two correction passes with joint scoring, using the typed syllables and up to 48 preceding characters to repair small homophone errors; user words and exact full-query dictionary matches are left alone.
- **Short words.** Exact candidates keep their dictionary order unless the language model's scores, with the text before the cursor when there is any, give the short-word policies a clear reason to change it. Without a context the policy also reads how often general text uses each word, and a first word that everyday conversation uses far more often keeps its place (`zhezhou` → 这周). Where nothing but the dictionary decides, a table precomputed for the dictionary sets the order. The characters of a single syllable are ordered by the language model after a context and by how often modern text uses them without one.
- **Phrases outside the dictionary.** For an input of three to five syllables that is neither a dictionary entry nor a user word, the dictionary supplies whole-phrase drafts for every way of cutting the input. The language model scores each by how well it stands as a clause of its own, with the text before the cursor when there is any, and picks one; it then corrects the chosen draft against the typed syllables. This runs for full and Double Pinyin in either script; fuzzy Pinyin or a separator `'` in the input disables it. A phrase the user picks from behind the first one is kept as a user word.
- **English letters.** Where typed letters are also a Chinese reading, the language model compares the letters with the page's first readings in one call, with the preceding text; the letters go first only with a clear lead.
- **One-key completion.** Dictionary and strong-transition completions are shown at once. The language model reranks a wider set of dictionary words in the background and replaces the shown completion only when the gain is clear.
- **Tab continuation in long sentences.** The language model proposes the next characters and scores the ways to finish the current word or continue with the next phrase; the Tab policy picks one or shows nothing.

### Runtime behavior
- Everything is computed locally on the CPU with the bundled ONNX Runtime; no network and no GPU are used.
- Only the engine process loads the model, in the background. Ordinary candidates, selection, commitment and dictionary completion do not wait for it.
- A language-model call has a 100 ms deadline and a long-sentence Tab result 80 ms; a late result is dropped and the existing result stays.
- The model sizes its thread pool from the fastest CPU tier, with four to eight workers. It falls back to the physical or system CPU count when tier information is unavailable.
- Only the text before the cursor is read as context, at most 1,024 UTF-16 code units, and never from secure fields.

## Benchmarks
The test methods, the corpus and the scoring rules are in [BENCHMARK.md](BENCHMARK.md). The cases are those of Cassotis IME for Windows, taken from the developer's own novel [**Elegance in Timelessness** (永恒的舞动)](https://www.qidian.com/book/1037259117/) and kept separate from all training data. ## Configuration
Open **Settings…** from the input menu, or press Ctrl+Shift+F10. Every confirmed change is saved and applied at once.

Important options include:
- simplified or traditional dictionary and the Pinyin scheme (Full Pinyin or one of seven Double Pinyin schemes)
- individual fuzzy-Pinyin rules
- candidates per page (3 to 9), paging and completion keys, and five individually switchable shortcuts
- Shift or Caps Lock as the Chinese/English key (Shift by default)
- remembering the Chinese/English mode per application (on by default)
- English recognition in Chinese mode (on by default)
- whether a full stop typed after digits becomes a decimal point (on by default)
- symbols kept half-width in Chinese punctuation (the Markdown preset by default)
- font, size, color theme and the optional three-row view
- the candidate window anchored at the start of the input or following the caret (anchored by default)
- `;` and `'` for the second and third candidate (off by default)
- Chinese/English mode hints beside the caret (on by default)
- custom phrases, with explicit Add / Save Changes actions, duplicate priority and JSON import/export
- importing word frequencies from another input method, in Advanced
- logging in Advanced (off by default; logs go to `~/Library/Logs/CassotisIME/`)
- ranking-context debug display in Advanced (off by default, independent of logging)

Display preferences are kept in the UserDefaults of `org.cassotis.inputmethod.Cassotis`; engine settings and learned data in `~/Library/Application Support/CassotisIME/`. See the [configuration guide (Chinese)](CONFIGURATION.md) for every key and option.

## Version History
The milestones of the macOS version, above all of its models. Each release follows a release of Cassotis IME for Windows, named in brackets; every release's full changes are in the [changelog](CHANGELOG.md) and the [release notes](https://github.com/shenmin/cassotis-ime-mac/releases).

**v0.1.0 (build 1, Windows v1.27.0): the first release.** A native InputMethodKit / AppKit input method with a Free Pascal engine process, local ONNX inference and simplified and traditional dictionaries; full Pinyin, abbreviations, six Double Pinyin schemes, fuzzy Pinyin, local learning and Tab completion; a two-row candidate window with eight color options, a Chinese/English bubble at the caret, settings that save automatically, and a signed graphical installer that keeps settings and learned words.

**v0.2.0 (build 2, Windows v1.29.0): the scores of Delphi on Apple silicon.** Context-aware short-word reranking, literary phrase recovery for long sentences, the optional three-row candidate view with mouse selection across rows, and exact specialist vocabulary. Comparisons against the minimum integer and floating-point intermediates are written so that Free Pascal on Apple silicon keeps the candidate paths and scores of Delphi.

**v1.0.0 (build 3, Windows v1.31.0): a shared character language model.** It replaces the RBT3 short-context model for long sentences, contextual short words, mixed abbreviations and Tab continuation; short completion is reranked in the background, and long completion compares finishing the current word with following phrases and predicted characters.

**v2.0.0 (build 4, Windows v2.2.0): one language model.** macOS 1.0.0 carried the eleven neural graphs of Windows v1.31.0, each for one stage of one input path. One character language model and seven compact units replace them, and the retired graphs, indexes and hosts leave the application. Phrases of three to five syllables outside the dictionary are composed by the model and corrected against the typed Pinyin. English recognition in Chinese mode, U/I/V quick input, decimal periods after digits, the Markdown punctuation preset, a per-application Chinese/English mode and ordered custom phrases arrive in the same release.

**v2.1.0 (build 5, Windows v2.4.0): traditional Chinese through the model.** Traditional candidates and context are scored through their simplified equivalents, while candidates, pages, committed text and Tab completion keep Taiwan's character forms. Word frequencies exported by other input methods can be imported, and a debug mode shows the ranking context.

**v2.5.0 (build 6, Windows v2.5.0): the word frequencies of general text.** The short-word policy reads how often general text uses each word, so that common words come first without context, and word transitions are loaded per query. Every character of a syllable can be paged to, Caps Lock can switch modes, and the model's threads follow the fastest core tier. From this release the macOS version follows the Windows version number.

**v2.6.0 (build 7, Windows v2.6.0): two models decide a correction.** The Pinyin-conditioned correction and the language model decide together whether a long sentence is rewritten, and a word can be swapped whole for another of the same Pinyin. Short words with a context get a policy of their own, single characters keep their usage order without context, and after a whole syllable's own characters those of its split into two syllables can be chosen as well (`shu` in `shua`).

**v2.7.0 (build 8, Windows v2.7.0): everyday conversation.** The language model continued its training on everyday dialogues and its six policies were refit; without context, a first choice that conversation uses far more often keeps its place. Phrase generation and correction run for traditional and Double Pinyin input, single characters after a context are ordered by the model, a sentence the correction changed is checked once more, and Zhineng ABC joins the Double Pinyin schemes.
