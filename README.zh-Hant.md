Cassotis IME macOS 版（言泉輸入法 macOS 版）是一個面向 Apple 晶片 Mac 的實驗性中文拼音輸入法。原生的 InputMethodKit / AppKit 前端與一個以 Free Pascal 撰寫的獨立引擎處理程序通訊；引擎移植自 [Cassotis IME Windows 版](https://github.com/shenmin/cassotis-ime)，詞庫由 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 產生。候選排序全部在本機 CPU 上完成，核心是一個由本專案訓練的字元級語言模型。

macOS 2.1.0（build 5）對標 Cassotis IME 與 Cassotis Lexicon v2.4.0：引擎和詞庫跟進已發布的 v2.4.0 標籤；語言模型和緊湊排序單元繼續與 Windows 版共用。它支援 Apple 晶片和 macOS 14 及以上。已驗證的環境和已知限制請見 [COMPATIBILITY.md](COMPATIBILITY.md)，產品介紹請見[官網](https://www.yanquan.org/mac)。

專案目前重點：
- 與 Windows 版的每個版本保持對齊，並在同一套基準上核對；
- 透過公開的 InputMethodKit 和 AppKit 介面融入 macOS 文字輸入，不需要輔助使用或輸入監控權限；
- 提供經過簽章與公證、不需連網也不需要 GPU 的安裝套件。

## 名稱來源
英文名 **Cassotis** 源自 Delphi 神廟內的一眼聖泉。傳說女祭司皮媞亞（Pythia）在發布神諭前會飲用此泉水，以進入通靈狀態。這眼泉水被視為預言與靈感的真正源頭，也是神諭誕生之地，呼應了從 Delphi 到人類語言的路徑。

中文名 **言泉** 既契合 Cassotis 作為預言之泉的意象，也取「言如泉湧」的寓意，寄託了對流暢、智慧輸入體驗的期許。

## 主要功能
- **原生輸入法**：InputMethodKit 輸入來源，AppKit 候選視窗從不搶走應用程式的輸入焦點。組字、分段選詞和送出可用於原生文字欄位、WebKit、Chrome、Electron 和終端機；密碼欄位保持系統的安全輸入行為。
- **候選視窗**：預設兩行：第一行最多九個編號候選、不換行，第二行是常駐的 Tab 補全區，右側顯示 logo 和版本號。翻頁時可展開為三行候選，數字鍵和空白鍵選擇目前行的詞，滑鼠可直接選擇任一可見行。使用者詞旁的小紅 × 可將其刪除。八種配色，字級 12 至 32 點（預設 14 點），即時預覽。
- **中英文切換**：單獨按下 Shift 切換中英文，游標旁的短暫氣泡顯示 logo 和「中」或「英」。預設每個應用程式分別記住自己的中英文狀態。按住修飾鍵期間若按了其他鍵或點按了滑鼠，單獨修飾鍵的切換會被取消；前端為此比較系統範圍的事件計數，不讀取按鍵內容。
- **英文辨識**：中文全拼、半形輸入時，英文單字和名稱（如 `pro`、`markdown`、`Effie`）、帶大寫字母的輸入以及曾以字母送出的輸入，可顯示在編號候選之前，並保留大小寫。輸入沒有整詞中文讀法時預設選中，空白鍵原樣送出；有中文讀法時（如 `bug`、`mac`），由語言模型結合上文在字母與中文之間權衡。方向鍵和滑鼠可在字母和中文候選之間選擇，中文候選的數字編號不變；選擇字母會被記住，但不會新增使用者詞。預設開啟，可在設定中關閉；雙拼仍按中文處理。
- **一鍵補全**：Tab 補全區每次只顯示一個可信的續寫方案，按設定的按鍵即可補全。使用者詞、基礎詞庫 exact 詞和離線複核的強轉移補全立即顯示；語言模型隨後在背景重新排序，游標前有文字時一併參考。在長句中，它補完目前的詞或續寫後面的短語，把握不足時不提示。預測結果使用主題強調色；只是把已輸入的詞接在一起時，使用一般文字顏色。古詩可從開頭幾個音節補全，完整輸入一句後還可提示下一句，例如「春眠不覺曉，處處聞啼鳥」。
- **長句**：受詞庫約束的路徑搜尋產生完整候選（例如 `womenjintian` → `我們今天`），同時保留前綴候選供分段送出。語言模型在完整候選中選擇；簡體全拼模式還會對照輸入的拼音和輸入位置之前的文字，修正選中句子裡少量的同音錯字。
- **短詞**：多個精確候選競爭時由語言模型判斷，游標前有已送出的文字時一併參考。
- **短語**：簡體模式下，三到五個音節、詞庫裡沒有的輸入（例如 `jiuguize` → `旧规则`），由詞庫中的詞組出若干整句方案，語言模型結合游標前的文字選出一個，再對照輸入的拼音修正同音字；把握接近時，首選之後最多再提供兩個整句。
- **拼音方案**：全拼及六種可選雙拼方案（微軟雙拼、小鶴雙拼、自然碼雙拼、搜狗雙拼、紫光雙拼和拼音加加）共用候選排序與使用者學習資料；模糊音規則可分別設定；支援首字母簡拼（例如 `jt` → `今天`）；以 `v` 輸入 ü（`lv`、`nv`，也接受 `lue`/`nue` 和 `jv`/`qv`/`xv`）。
- **詞庫與學習**：簡體基礎庫、繁體基礎庫與使用者詞庫相互分離。使用者詞依目前的簡繁模式顯示，不需重新學習。專業詞彙只在精確輸入時出現。無法解釋為音節的字母以紅色標示，不改動輸入。
- **快捷輸入**：`ufh` 輸入符號，`uxh` 輸入數字序號，`usx` 輸入數學符號，`urq` / `usj` 輸入目前日期和時間等；`i123.45` 或 `v123.45` 轉換中文數字及金額大寫，數字鍵繼續輸入數字，按候選旁的 `a/b/c/d` 選詞。雙拼需以 Shift+U/I/V 進入。詳見[快捷輸入說明](QUICK_INPUT.md)。
- **中文標點**：中文標點、半形輸入時，緊接在數字後的句號輸出為小數點；可在設定中指定原樣輸出的符號，也可一鍵換成 Markdown 組合或標準中文標點。預設的 Markdown 組合為 ``-#*+_=`~[]<>|@``；逗號、句號、圓括號和引號仍按中文習慣輸入，反斜線輸入頓號 `、`。
- **自訂短語**：以英文字母縮寫呼叫文字，按 Tab 原樣送出；支援多行內容、排序、重複縮寫優先順序及 Windows 相容的 JSON 匯入、匯出。填寫縮寫和內容後點擊「添加短语」加入清單；編輯已有條目時使用「保存修改」或「取消编辑」。
- **設定**：左側分類的設定視窗，確認的修改立即儲存；直接按鍵錄製快捷鍵，字型名稱可自動補全。記錄檔預設關閉。
- **完全本機**：不連網，不需要 GPU。引擎啟動期間輸入的按鍵會暫存，就緒後照常轉換；語言模型尚未載入或無法使用時，候選照常提供，只是不經過語言模型排序。

## 2.1.0 的改進

- **帶入選詞習慣。** 在「高級」頁匯入其他輸入法匯出的詞語、完整拼音和使用次數，支援逗號或 Tab 分隔文字；匯入前說明格式和影響，完成後顯示實際匯入數量。詳見[輸入頻次匯入](CONFIGURATION.md#输入频次导入)。
- **常用詞與未完短語更穩。** 沒有上文時，語料證據明顯更強的常用首選不再輕易被替換；短語同時考慮不帶逗號的評分，適合接著輸入。詞庫補充日常表達。
- **短語和前綴更穩妥。** 末音節尚未輸完的詞保留在生成短語之前，檢查其他合法音節切分，重新評分糾錯結果，減少生硬或近似重複的次選。需要額外音節的長詞放在 Tab 補全區。
- **繁體輸入更準確。** 共用模型按對應簡體評分，候選、翻頁、上屏和 Tab 補全統一輸出台灣常用繁體字形；「著名」等詞保留正確讀音。
- **Tab 建議更貼合輸入。** 有充分依據的常用詞優先於生僻專業詞，不再用讀音不符的建議替換補全。詞庫增加常用表達並修正讀音。
- **需要時查看排序上文。** 「高级 → 启用调试模式」在候選窗右下角顯示上文及來源，不改變視窗尺寸。預設關閉，獨立於日誌開關。

## 下載與安裝
- **下載**：從 [Releases](https://github.com/shenmin/cassotis-ime-mac/releases) 頁面下載 `cassotis-ime-macos-<版本號>-arm64-installer-signed.dmg`。磁碟映像約 300 MB，包含簡繁基礎詞庫和語言模型。正式發布的映像使用 Sunisoft Limited 的 Developer ID 簽章，並經過 Apple 公證。
- **系統需求**：Apple 晶片的 Mac，macOS 14 及以上。不需要終端機指令、編譯器、Python、連網或 GPU。
- **安裝**：開啟磁碟映像，按兩下「言泉输入法安装器」，點按「安装」。安裝程式會請求 macOS 啟用輸入來源；若出現確認提示，請點按「允許」。顯示「安装完成」後，從選單列的輸入選單選擇「言泉输入法」，輸入 `nihao` 後按空白鍵即可打出「你好」。若尚未啟用，請點按「重试启用」，或點按「打开键盘设置」手動加入。
- **macOS 27**：系統可能只開啟鍵盤設定而不顯示確認提示。請在「文字輸入 → 編輯 → + → 中文（簡體）」中加入「言泉输入法」，再返回安裝程式；安裝程式會核實啟用狀態。
- **升級**：直接執行新版本的安裝程式覆蓋安裝。設定和學習紀錄會保留；安裝程式顯示進度，失敗時提供記錄檔和重試。
- **解除安裝**：先在系統設定中移除輸入來源，再使用安裝程式中的解除安裝功能。設定和學習紀錄會保留。

## 架構
- `src/macos`：InputMethodKit 輸入控制器，以及 AppKit 候選視窗、狀態氣泡和設定視窗（Objective-C++）。
- `src/service`、`src/ipc`：引擎處理程序的服務和 Unix socket 通訊協定。
- `src/engine`、`src/dictionary`：拼音解析、候選產生、排序與使用者學習，移植自 Windows 版。
- `src/host`：語言模型的承載；`src/host/native` 是連接 ONNX Runtime 的 C++ 橋接和注意力運算子。
- `src/common`：設定、型別和平台適配。
- `src/installer`：圖形安裝程式。
- `tools/dictionary`、`tools/control`：詞庫匯入工具和輸入來源控制工具。
- `data`：語言模型（`data/models/char_lm`，以編號分片儲存）、模型校驗值和詞庫輸入雜湊值。
- `scripts`、`resources`：建置、安裝和封裝腳本；圖示和應用程式資源。
- `third_party`：ONNX Runtime 的標頭檔和版本，以及隨附元件的授權條款與聲明。

處理程序、通訊協定和故障復原請見[架構文件](docs/ARCHITECTURE.md)。

## 執行階段檔案
- `Cassotis.app/Contents/MacOS/Cassotis`：輸入法前端，由 macOS 為輸入來源啟動。
- `Cassotis.app/Contents/MacOS/cassotis-engine`：引擎處理程序，載入詞庫和語言模型。前端以 `--serve` 啟動它，經私有的 Unix socket 通訊。
- `Cassotis.app/Contents/Frameworks/libcassotis_ort.dylib` 和 `libonnxruntime.1.20.1.dylib`：語言模型橋接及其執行階段程式庫，只由引擎處理程序載入。
- `Cassotis.app/Contents/Resources/models/char_lm`：語言模型、詞表、拼音讀音表和執行清單。
- `Cassotis.app/Contents/Resources/dictionaries`：簡繁基礎詞庫（`dict_sc.db`、`dict_tc.db`）。

沒有引擎處理程序就無法轉換輸入。請求失敗或逾時時，前端送出最後可見的組字內容，把目前的按鍵交給應用程式，並重新啟動引擎。缺少模型檔案時輸入法仍可使用，只是候選不經過語言模型排序。

## 建置與安裝（快速開始）
前置條件：Apple 晶片的 Mac、Free Pascal 3.2.2、Xcode 命令列工具和 Python 3.11 及以上，不依賴 Lazarus/LCL。準備 [Cassotis Lexicon v2.4.0](https://github.com/shenmin/cassotis-lexicon) 的產生資產，將 `CASSOTIS_LEXICON_ROOT` 指向該目錄（`/path/to/...` 為佔位路徑）：

```sh
./scripts/check_environment.sh
export CASSOTIS_LEXICON_ROOT="/path/to/cassotis-lexicon"
./build_all.sh
./install.sh
```

應用程式輸出至 `build/arm64/Cassotis.app`，安裝至目前使用者的 `~/Library/Input Methods/Cassotis.app`；腳本請勿以 `sudo` 執行。在「系統設定 → 鍵盤 → 文字輸入」中加入言泉輸入法，再從輸入選單選用。若輸入來源清單沒有更新，可登出後重新登入。

`build_all.sh` 依序建置語言模型橋接、引擎、簡繁詞庫、前端和安裝程式，並在核對 SHA-256 後把 `data/models/char_lm` 中的編號分片合併為應用程式攜帶的 `char_lm.onnx`。首次建置會下載官方 ONNX Runtime 1.20.1 arm64 發行套件並核對固定的雜湊值。`./rebuild_all.sh` 清理後完整重建，`./uninstall.sh` 解除安裝輸入法並保留學習紀錄，`./scripts/package.sh` 產生安裝用的磁碟映像。選項、封裝和簽章請見 [BUILD.md](BUILD.md)。

## 詞庫流程
基礎詞庫是 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 的 schema 24 SQLite 資料庫，由其 `data/generated/` 下的 26 個產生檔案建置：
- 詞表 `dict_unihan_sc.txt`、`dict_unihan_tc.txt`、`dict_clean_sc.txt`、`dict_clean_tc.txt`（`pinyin<TAB>text<TAB>weight`）；
- 同一目錄中由語料訓練的表：詞間轉移先驗、補全先驗和短詞首選表。

建置時依 [data/lexicon-inputs.json](data/lexicon-inputs.json) 核對每個檔案，再匯入 `dict_sc.db` 和 `dict_tc.db`，放進應用程式套件。v2.4.0 詞庫有簡體 259,524 筆、繁體 260,404 筆讀音紀錄（含單字）。使用者詞庫、引擎設定和學習資料位於 `~/Library/Application Support/CassotisIME/`，替換應用程式不會覆蓋這些檔案。

## 模型與排序

### 2.0.0：只留一個語言模型
macOS 1.0.0 搭載的是 Windows v1.31.0 的各個獨立模型：11 個神經網路圖，分別負責排序、評分、生成和糾錯，每個只負責某條輸入路徑的某個階段。macOS 2.0.0 接手了 Windows v2.0.0 和 v2.2.0 的整合：

- **一個模型。** 一個約 1.5 億參數的字元級自迴歸語言模型（11 層、1024 維、12,017 個字元的詞表、8 位元量化），由本專案以獨立的中文語料訓練，既作為一般語言模型，也以拼音為條件。它為長句的完整候選評分，對照輸入的音節修正選中的句子，在短詞候選中選擇，為一鍵補全重新排序，並產生和選擇長句的 Tab 續寫。2.1.0 延續這一模型，權重與 Windows v2.4.0 逐位元組相同；退役的模型圖、索引和承載程式已從應用程式中刪除。
- **七個緊湊單元。** 留下三個結構排序器，用於長句搜尋和完整候選池。另有四個小型梯度提升策略，把語言模型的分數變成決定：長句選擇、短詞選擇、一鍵補全和 Tab 續寫。它們以與 Windows 相同的參數編譯進引擎。短詞無上下文時的選擇是詞庫裡預先算好的一張表。
- **分數與呼叫方式無關。** 模型採用固定的量化範圍，注意力由自己的運算子計算；Apple 晶片上的 NEON 核心保持與 Windows 核心相同的加總順序。同一段文字無論怎樣分批、之前算過什麼，得到的分數都相同，因此長句逐鍵打出來，與同樣的拼音一次輸入，候選是一樣的。
- **以後只改一處。** 語言模型變好，所有輸入路徑一起受益；四個策略在 Windows 上以引擎的實際執行紀錄重新擬合。

### 現在的排序方式
繁體輸入時，模型先依對應簡體字評分，模型產生的補全由引擎轉換為台灣常用繁體字形；前景選詞與背景補全使用同一個模型。

- **長句**：受詞庫約束的搜尋產生完整候選，兩個排序器決定哪些路徑在剪枝中保留，第三個排序器為完整候選池排序。語言模型為排在前面的候選評分，長句策略選出第一和第二候選。簡體、全拼輸入時，模型還會對照輸入的音節和輸入位置之前最多 48 個字改寫選中的句子，修正少量同音錯字；使用者詞和完整拼音的詞庫精確匹配不會被改動。
- **短詞**：精確候選預設保持詞庫順序；只有語言模型的分數（游標前有文字時一併參考）給出明確理由時，短詞策略才調整順序。只有詞庫可以依據時，由預先算好的那張表決定誰排在前面。
- **詞庫外的短語**：三到五個音節、既不是詞庫詞也不是使用者詞的輸入，先由詞庫提供各種切分下的整句草稿；語言模型依「作為一個完整分句是否通順」為它們評分並選出一個，游標前有文字時一併參考；再對照輸入的音節修正選中的草稿。雙拼同樣適用；開啟模糊音、輸入中帶分隔符 `'` 或使用繁體詞庫時不啟用。使用者選過的非首選短語會被記為使用者詞。
- **英文字母**：輸入的字母同時也是中文讀法時，語言模型結合上文，在一次呼叫中比較字母與本頁前幾個讀法；字母只有明顯領先時才排在前面。
- **一鍵補全**：詞庫補全和強轉移補全立即顯示。語言模型在背景為更大範圍的詞庫詞重新排序，優勢明確時才替換已顯示的補全。
- **長句 Tab 續寫**：語言模型提供後面的字，並比較補完目前的詞和續寫後面短語的各種方案；Tab 策略選出一個，或者不提示。

### 執行方式
- 全部在本機 CPU 上以隨附的 ONNX Runtime 計算，不連網，不使用 GPU。
- 模型只由引擎處理程序在背景載入。一般候選、選詞、送出和詞庫補全不等待它。
- 語言模型呼叫的期限為 100 ms，長句 Tab 結果為 80 ms；逾時的結果會被捨棄，保留既有結果。
- 模型的執行緒數等於處理器核心數，最少 4 個，最多 8 個。
- 只讀取游標前的文字作為上下文，最多 1,024 個 UTF-16 單元，從不讀取密碼欄位。

新版及未改動的 macOS v2.0.0 程式均以原生 arm64 在 Apple M2 Pro、32 GiB 記憶體、macOS 27.0.1 上依序量測，使用簡體詞庫和 8 個模型執行緒。延遲單位為 ms，只計引擎本身，不含 InputMethodKit、IPC 和繪製。本輪最終量測在暫停螢幕共享後開始，跨輪耗時仍可能受系統負載影響。

## 設定
從輸入選單開啟「设置…」，或按 Ctrl+Shift+F10。確認的修改立即儲存並生效。

主要選項包括：
- 簡繁詞庫和拼音方案（全拼或六種雙拼之一）
- 逐項的模糊音規則
- 每頁候選數（3 至 9）、翻頁鍵和補全鍵，以及五個可分別啟用的快捷鍵
- 依應用程式記住中英文狀態（預設開啟）
- 中文模式下的英文辨識（預設開啟）
- 數字後的句號是否輸出小數點（預設開啟）
- 中文標點下保持半形的符號（預設為 Markdown 組合）
- 字型、字級、配色和可選的三行展開
- 自訂短語（新增／儲存修改、排序及 JSON 匯入／匯出）
- 進階頁的記錄檔（預設關閉；位於 `~/Library/Logs/CassotisIME/`）
- 進階頁的排序上文除錯顯示（預設關閉，獨立於記錄檔）

顯示偏好儲存在 `org.cassotis.inputmethod.Cassotis` 的 UserDefaults 中；引擎設定和學習資料位於 `~/Library/Application Support/CassotisIME/`。全部按鍵和選項請見[使用與設定（簡體中文）](CONFIGURATION.md)。

## 版本歷史
以下每段記錄的是該版本當時引入的內容。其中的獨立模型已在 2.0.0 退役，現在實際執行的部分請見上文「模型與排序」。

Cassotis IME macOS 版 v0.1.0（build 1）是第一個版本，以 Cassotis IME 與詞庫 v1.27.0 為基線：原生 InputMethodKit / AppKit 輸入法，搭配 Free Pascal 引擎處理程序、本機 ONNX 推論和簡繁詞庫；全拼、簡拼、六種雙拼、模糊音、本機學習和 Tab 補全；兩行候選視窗與八種配色、游標旁的中英文狀態氣泡、自動儲存的設定，以及保留設定和學習紀錄的已簽章圖形安裝程式。

Cassotis IME macOS 版 v0.2.0（build 2）移植 v1.29.0：結合上下文的短詞重排、長句的文學短語復原、可選的三行候選展開及跨行滑鼠選詞，以及只在精確輸入時出現的專業詞彙。與最小整數的比較和浮點中間結果依 Delphi 的語意改寫，使 Apple 晶片上的 Free Pascal 得到相同的候選路徑和分數。

Cassotis IME macOS 版 v1.0.0（build 3）移植 v1.31.0：共用的字元語言模型取代 RBT3 短上下文模型，負責長句、帶上下文的短詞、混合簡拼和 Tab 續寫；短詞補全在背景重排，長句補全比較補完目前的詞、後續短語和預測的後續字。

Cassotis IME macOS 版 v2.0.0（build 4）移植 v2.2.0，以一個字元語言模型和七個緊湊單元取代 11 個神經網路圖。詞庫外三到五個音節的短語由語言模型組成，並對照輸入的拼音修正。新增中文模式下的英文辨識、U/I/V 快捷輸入、數字後的小數點、Markdown 標點組合和依應用程式記住的中英文狀態；糾錯後的分段送出與復原保留原始按鍵，鼻音邊界有歧義時單字仍可選擇。另加入自訂短語、末音節繼續輸入時保留補全，以及無上下文短語評分改進。詞庫在先前 389 個新增項之外，再增加簡繁各 67 個回覆、集合及程式庫用語。
