Cassotis IME macOS 版（言泉输入法 macOS 版）是一个面向 Apple 芯片 Mac 的实验性中文拼音输入法。原生的 InputMethodKit / AppKit 前端与一个用 Free Pascal 编写的独立引擎进程通信；引擎移植自 [Cassotis IME Windows 版](https://github.com/shenmin/cassotis-ime)，词库由 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 生成。候选排序全部在本机 CPU 上完成，核心是一个由本项目训练的字符级语言模型。

macOS 2.5.0（build 6）对标 Cassotis IME 与 Cassotis Lexicon v2.5.0：引擎和词库跟进已发布的 v2.5.0 标签；语言模型和紧凑排序单元继续与 Windows 版共享。它支持 Apple 芯片和 macOS 14 及以上。已验证的环境和已知限制见 [COMPATIBILITY.md](COMPATIBILITY.md)，产品介绍见[官网](https://www.yanquan.org/mac)。

v2.5.0 源码正在准备发布；下方下载仍指向当前已发布的安装包。

项目当前重点：
- 与 Windows 版的每个版本保持对齐，并在同一套基准上核对；
- 通过公开的 InputMethodKit 和 AppKit 接口融入 macOS 文字输入，不需要辅助功能或输入监控权限；
- 提供经过签名和公证、不联网也不需要 GPU 的安装包。

## 名称来源
英文名 **Cassotis** 源自 Delphi 神庙内的一眼圣泉。传说女祭司皮媞亚（Pythia）在发布神谕前会饮用此泉水，以进入通灵状态。这眼泉水被视为预言与灵感的真正源头，也是神谕诞生之地，呼应了从 Delphi 到人类语言的路径。

中文名 **言泉** 既契合 Cassotis 作为预言之泉的意象，也取“言如泉涌”的寓意，寄托了对流畅、智能输入体验的期许。

## 主要特性
- **原生输入法**：InputMethodKit 输入源，AppKit 候选窗从不抢走应用的输入焦点。组合、分段选词和上屏可用于原生文本框、WebKit、Chrome、Electron 和终端；密码框保持系统的安全输入行为。
- **候选窗**：默认两行：第一行最多九个编号候选、不换行，第二行是常驻的 Tab 补全区，右侧显示 logo 和版本号。翻页时可展开为三行候选，数字键和空格选择当前行的词，鼠标可直接选择任一可见行。单音节输入可翻页查看全部单字，包括候选超过 256 个的读音。用户词旁的小红 × 可将其删除。八种配色，字号 12 至 32 点（默认 14 点），实时预览。
- **中英文切换**：单独按下 Shift 切换中英文，光标旁的短暂气泡显示 logo 和“中”或“英”。可在外观页关闭气泡。切换到言泉时显示当前状态，英文模式下进入输入框也会提醒。可选择 Caps Lock 代替 Shift；目前不区分短按与长按，使用前请阅读 [配置说明](CONFIGURATION.md)。默认每个应用分别记住自己的中英文状态。按住修饰键期间若按了其他键或点击了鼠标，单独修饰键的切换会被取消；前端为此比较系统范围的事件计数，不读取按键内容。
- **英文识别**：中文全拼、半角输入时，英文单词和名称（如 `pro`、`markdown`、`Effie`）、带大写字母的输入以及曾按字母上屏的输入，可显示在编号候选之前，并保留大小写。输入没有整词中文读法时默认选中，空格原样上屏；有中文读法时（如 `bug`、`mac`），由语言模型结合上文在字母与中文之间权衡。方向键和鼠标可在字母和中文候选之间选择，中文候选的数字编号不变；选择字母会被记住，但不会新增用户词。默认开启，可在设置中关闭；双拼仍按中文处理。
- **一键补全**：Tab 补全区每次只显示一个可信的续写方案，按配置键即可补全。用户词、基础词库 exact 词和离线复核的强转移补全立即显示；语言模型随后在后台重新排序，光标前有文字时一并参考。在长句中，它补完当前词或续写后面的短语，把握不足时不提示。预测结果使用主题强调色；只是把已输入的词拼在一起时，使用普通文字颜色。古诗可从开头几个音节补全，完整输入一句后还可提示下一句，例如“春眠不觉晓，处处闻啼鸟”。
- **长句**：受词库约束的路径搜索给出完整候选（例如 `womenjintian` → `我们今天`），同时保留前缀候选供分段上屏。语言模型在完整候选中选择；简体全拼模式还会对照输入的拼音和输入位置之前的文字，修正选中句子里少量的同音错字。
- **短词**：多个精确候选竞争时由语言模型结合上文和通用文本词频判断；没有上文时，明显生僻的词不会挤掉常用首选。
- **短语**：简体模式下，三到五个音节、词库里没有的输入（例如 `jiuguize` → `旧规则`），由词库中的词拼出若干整句方案，语言模型结合光标前的文字选出一个，再对照输入的拼音修正同音字；把握接近时，首选之后最多再给出两个整句。
- **拼音方案**：全拼及六种可选双拼方案（微软双拼、小鹤双拼、自然码双拼、搜狗双拼、紫光双拼和拼音加加）共用候选排序与用户学习数据；模糊音规则可分别配置；支持首字母简拼（例如 `jt` → `今天`）；用 `v` 输入 ü（`lv`、`nv`，也接受 `lue`/`nue` 和 `jv`/`qv`/`xv`）。
- **词库与学习**：简体基础库、繁体基础库与用户词库相互分离。用户词按当前的简繁模式显示，无需重新学习。专业词汇只在精确输入时出现。无法解释为音节的字母以红色标出，不改动输入。
- **快捷输入**：`ufh` 输入符号，`uxh` 输入数字序号，`usx` 输入数学符号，`urq` / `usj` 输入当前日期和时间等；`i123.45` 或 `v123.45` 转换中文数字及金额大写，数字键继续录入，按候选旁的 `a/b/c/d` 选词。双拼需用 Shift+U/I/V 进入。详见[快捷输入说明](QUICK_INPUT.md)。
- **中文标点**：中文标点、半角输入时，紧跟在数字后的句号输出为小数点；可在设置中指定原样输出的符号，也可一键换成 Markdown 预设或标准中文标点。默认的 Markdown 预设为 ``-#*+_=`~[]<>|@``；逗号、句号、圆括号和引号仍按中文习惯输入，反斜杠输入顿号 `、`。
- **自定义短语**：以英文字母缩写调用文字，按 Tab 原样上屏；支持多行内容、排序、重复缩写优先级及 Windows 兼容的 JSON 导入、导出。填写缩写和内容后点击“添加短语”进入列表；编辑已有条目时使用“保存修改”或“取消编辑”。
- **设置**：左侧分类的设置窗口，确认的修改立即保存；直接按键录制快捷键，字体名称可自动补全。日志默认关闭。
- **完全本地**：不联网，不需要 GPU。引擎启动期间输入的按键会暂存，就绪后照常转换；语言模型尚未加载或不可用时，候选照常给出，只是不经过语言模型排序。

## 2.5.0 的改进

- **短词选得更合适。** 通用文本词频参与模型排序，无上文时更好地保留常用首选；短语缺少完整词条时，可利用已有词间转移生成候选。
- **单音节候选翻得全。** 超过256个单字的音节也能翻到末尾，减少过滤后跨页重复；`ng`、`hm` 可选到“嗯”“噷”。
- **状态提醒更清楚。** 切入言泉及焦点交接时保留光标气泡，进入英文状态的文本框也会提醒。可在“外观”中关闭。
- **可选 Caps Lock 切换。** 可将中英文切换键设为 Caps Lock，未完成的拼音先按原文上屏；目前不区分物理短按与长按。
- **更新词库。** 使用 Cassotis Lexicon v2.5.0，词间转移改为按需读取，减少启动加载；继续使用原有的单一神经模型。

## 2.1.0 的改进

- **带入选词习惯。** 在“高级”页导入其他输入法导出的词语、完整拼音和使用次数，支持逗号或 Tab 分隔文本；导入前说明格式和影响，完成后显示实际导入数量。详见[输入频次导入](CONFIGURATION.md#输入频次导入)。
- **常用词与未完短语更稳。** 没有上文时，语料证据明显更强的常用首选不再轻易被替换；短语同时考虑不带逗号的评分，适合接着输入。词库补充日常表达。
- **短语和前缀更稳妥。** 末音节尚未输完的词保留在生成短语之前，检查其他合法音节切分，重新评分纠错结果，减少生硬或近似重复的次选。需要额外音节的长词放在 Tab 补全区。
- **繁体输入更准确。** 共享模型按对应简体评分，候选、翻页、上屏和 Tab 补全统一输出台湾常用繁体字形；“著名”等词保留正确读音。
- **Tab 建议更贴合输入。** 有充分依据的常用词优先于生僻专业词，不再用读音不符的建议替换补全。词库增加常用表达并修正读音。
- **需要时查看排序上文。** “高级 → 启用调试模式”在候选窗右下角显示上文及来源，不改变窗口尺寸。默认关闭，独立于日志开关。

## 下载与安装
- **下载**：从 [Releases](https://github.com/shenmin/cassotis-ime-mac/releases) 页面下载 `cassotis-ime-macos-<版本号>-arm64-installer-signed.dmg`。磁盘映像约 340 MB，包含简繁基础词库和语言模型。正式发布的映像使用 Sunisoft Limited 的 Developer ID 签名并经过 Apple 公证。
- **系统要求**：Apple 芯片的 Mac，macOS 14 及以上。不需要终端命令、编译器、Python、联网或 GPU。
- **安装**：打开磁盘映像，双击“言泉输入法安装器”，点击“安装”。安装器会请求 macOS 启用输入源；若出现确认提示，点击“允许”。显示“安装完成”后，从菜单栏的输入菜单选择“言泉输入法”，输入 `nihao` 后按空格即可打出“你好”。若尚未启用，点击“重试启用”，或点击“打开键盘设置”手动添加。
- **macOS 27**：系统可能只打开键盘设置而不弹出确认。请在“文字输入 → 编辑 → + → 中文（简体）”中添加“言泉输入法”，再返回安装器；安装器会核实启用状态。
- **升级**：直接运行新版本的安装器覆盖安装。设置和学习记录保留；安装器显示进度，失败时提供日志和重试。
- **卸载**：先在系统设置中移除输入源，再使用安装器中的卸载功能。设置和学习记录保留。

## 架构
- `src/macos`：InputMethodKit 输入控制器，以及 AppKit 候选窗、状态气泡和设置窗口（Objective-C++）。
- `src/service`、`src/ipc`：引擎进程的服务和 Unix socket 协议。
- `src/engine`、`src/dictionary`：拼音解析、候选生成、排序与用户学习，移植自 Windows 版。
- `src/host`：语言模型宿主；`src/host/native` 是连接 ONNX Runtime 的 C++ 桥接和注意力算子。
- `src/common`：配置、类型和平台适配。
- `src/installer`：图形安装器。
- `tools/dictionary`、`tools/control`：词库导入器和输入源控制工具。
- `data`：语言模型（`data/models/char_lm`，以编号分片保存）、模型校验值和词库输入哈希。
- `scripts`、`resources`：构建、安装和打包脚本；图标和应用资源。
- `third_party`：ONNX Runtime 的头文件和版本，以及随附组件的许可证和声明。

进程、协议和故障恢复见[架构文档](docs/ARCHITECTURE.md)。

## 运行时文件
- `Cassotis.app/Contents/MacOS/Cassotis`：输入法前端，由 macOS 为输入源启动。
- `Cassotis.app/Contents/MacOS/cassotis-engine`：引擎进程，加载词库和语言模型。前端以 `--serve` 启动它，经私有的 Unix socket 通信。
- `Cassotis.app/Contents/Frameworks/libcassotis_ort.dylib` 和 `libonnxruntime.1.20.1.dylib`：语言模型桥接及其运行库，只由引擎进程加载。
- `Cassotis.app/Contents/Resources/models/char_lm`：语言模型、词表、拼音读音表和运行清单。
- `Cassotis.app/Contents/Resources/dictionaries`：简繁基础词库（`dict_sc.db`、`dict_tc.db`）。

没有引擎进程就无法转换输入。请求失败或超时时，前端提交最后可见的组合串，把当前按键交给应用，并重新启动引擎。缺少模型文件时输入法仍可使用，只是候选不经过语言模型排序。

## 构建与安装（快速开始）
前置条件：Apple 芯片的 Mac、Free Pascal 3.2.2、Xcode 命令行工具和 Python 3.11 及以上，不依赖 Lazarus/LCL。准备 [Cassotis Lexicon v2.5.0](https://github.com/shenmin/cassotis-lexicon) 的生成资产，将 `CASSOTIS_LEXICON_ROOT` 指向该目录（`/path/to/...` 为占位路径）：

```sh
./scripts/check_environment.sh
export CASSOTIS_LEXICON_ROOT="/path/to/cassotis-lexicon"
./build_all.sh
./install.sh
```

应用输出到 `build/arm64/Cassotis.app`，安装到当前用户的 `~/Library/Input Methods/Cassotis.app`；脚本不要用 `sudo` 运行。在“系统设置 → 键盘 → 文字输入”中添加言泉输入法，再从输入菜单选用。若输入源列表没有刷新，可退出登录后重新登录。

`build_all.sh` 依次构建语言模型桥接、引擎、简繁词库、前端和安装器，并在核对 SHA-256 后把 `data/models/char_lm` 中的编号分片合并为应用携带的 `char_lm.onnx`。首次构建会下载官方 ONNX Runtime 1.20.1 arm64 发行包并核对固定的哈希。`./rebuild_all.sh` 清理后完整重建，`./uninstall.sh` 卸载输入法并保留学习记录，`./scripts/package.sh` 生成安装磁盘映像。选项、打包和签名见 [BUILD.md](BUILD.md)。

## 词库流程
基础词库是 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 的 schema 24 SQLite 数据库，由其 `data/generated/` 下的 28 个生成文件构建：
- 词表 `dict_unihan_sc.txt`、`dict_unihan_tc.txt`、`dict_clean_sc.txt`、`dict_clean_tc.txt`（`pinyin<TAB>text<TAB>weight`）；
- 同一目录中由语料训练的表：词间转移先验、补全先验和短词首选表。

构建时按 [data/lexicon-inputs.json](data/lexicon-inputs.json) 核对每个文件，再导入 `dict_sc.db` 和 `dict_tc.db`，放进应用包。v2.5.0 词库有简体 261,149 条、繁体 262,028 条读音记录（含单字）。用户词库、引擎设置和学习数据位于 `~/Library/Application Support/CassotisIME/`，替换应用不会覆盖这些文件。

## 模型与排序

### 2.0.0：只留一个语言模型
macOS 1.0.0 搭载的是 Windows v1.31.0 的各个独立模型：11 个神经网络图，分别承担排序、评分、生成和纠错，每个只负责某条输入路径的某个阶段。macOS 2.0.0 接过了 Windows v2.0.0 和 v2.2.0 的整合：

- **一个模型。** 一个约 1.5 亿参数的字符级自回归语言模型（11 层、1024 维、12,017 个字符的词表、8 位量化），由本项目用独立的中文语料训练，既作为普通语言模型，也以拼音为条件。它为长句的完整候选打分，对照输入的音节修正选中的句子，在短词候选中选择，为一键补全重新排序，并给出和选择长句的 Tab 续写。2.5.0 延续这一模型，权重与 Windows v2.5.0 逐字节相同；退役的模型图、索引和宿主已从应用中删除。
- **七个紧凑单元。** 留下三个结构排序器，用于长句搜索和完整候选池。另有四个小的梯度提升策略，把语言模型的分数变成决定：长句选择、短词选择、一键补全和 Tab 续写。它们以与 Windows 相同的参数编译进引擎。短词无上下文时的选择是词库里预先算好的一张表。
- **分数与调用方式无关。** 模型采用固定的量化范围，注意力由自己的算子计算；Apple 芯片上的 NEON 内核保持与 Windows 内核相同的求和顺序。同一段文字无论怎样分批、之前算过什么，得到的分数都相同，因此长句一键一键打出来，与同样的拼音一次给出，候选是一样的。
- **以后只改一处。** 语言模型变好，所有输入路径一起受益；四个策略在 Windows 上用引擎的实际运行记录重新拟合。

### 现在的排序方式
繁体输入时，模型先按对应简体字评分，模型生成的补全由引擎转换为台湾常用繁体字形；前台选词与后台补全使用同一个模型。

- **长句**：受词库约束的搜索给出完整候选，两个排序器决定哪些路径在剪枝中保留，第三个排序器为完整候选池排序。语言模型为排在前面的候选打分，长句策略选出第一和第二候选。简体、全拼输入时，模型还会对照输入的音节和输入位置之前最多 48 个字改写选中的句子，修正少量同音错字；用户词和完整拼音的词库精确匹配不会被改动。
- **短词**：精确候选默认保持词库顺序；只有语言模型的分数（光标前有文字时一并参考）给出明确理由时，短词策略才调整顺序。只有词库可以依据时，由预先算好的那张表决定谁排在前面。
- **词库外的短语**：三到五个音节、既不是词库词也不是用户词的输入，先由词库给出各种切分下的整句草稿；语言模型按“作为一个完整分句是否通顺”为它们打分并选出一个，光标前有文字时一并参考；再对照输入的音节修正选中的草稿。双拼同样适用；开启模糊音、输入中带分隔符 `'` 或使用繁体词库时不启用。用户选过的非首选短语会被记为用户词。
- **英文字母**：输入的字母同时也是中文读法时，语言模型结合上文，在一次调用中比较字母与本页前几个读法；字母只有明显领先时才排在前面。
- **一键补全**：词库补全和强转移补全立即显示。语言模型在后台为更大范围的词库词重新排序，优势明确时才替换已显示的补全。
- **长句 Tab 续写**：语言模型给出后面的字，并比较补完当前词和续写后面短语的各种方案；Tab 策略选出一个，或者不提示。

### 运行方式
- 全部在本机 CPU 上用随附的 ONNX Runtime 计算，不联网，不使用 GPU。
- 模型只由引擎进程在后台加载。普通候选、选词、上屏和词库补全不等待它。
- 语言模型调用的期限为 100 ms，长句 Tab 结果为 80 ms；超时的结果被丢弃，保留已有结果。
- 模型线程数优先按高性能核心数确定，最少 4 个、最多 8 个；系统未提供该信息时回退到物理或系统 CPU 计数。
- 只读取光标前的文字作为上下文，最多 1,024 个 UTF-16 单元，从不读取密码框。

## 配置
从输入菜单打开“设置…”，或按 Ctrl+Shift+F10。确认的修改立即保存并生效。

主要选项包括：
- 简繁词库和拼音方案（全拼或六种双拼之一）
- 逐项的模糊音规则
- 每页候选数（3 至 9）、翻页键和补全键，以及五个可分别启用的快捷键
- 按应用记住中英文状态（默认开启）
- 中文模式下的英文识别（默认开启）
- 数字后的句号是否输出小数点（默认开启）
- 中文标点下保持半角的符号（默认 Markdown 预设）
- 字体、字号、配色和可选的三行展开
- 光标旁的中英文状态提示（默认开启）
- 自定义短语（添加／保存修改、排序及 JSON 导入／导出）
- 高级页中的日志（默认关闭；日志位于 `~/Library/Logs/CassotisIME/`）
- 高级页中的排序上文调试显示（默认关闭，独立于日志）

显示偏好保存在 `org.cassotis.inputmethod.Cassotis` 的 UserDefaults 中；引擎设置和学习数据位于 `~/Library/Application Support/CassotisIME/`。全部按键和选项见[使用与设置](CONFIGURATION.md)。

## 版本历史
下面每段记录的是该版本当时引入的内容。其中的独立模型已在 2.0.0 退役，现在实际运行的部分见上文“模型与排序”。

Cassotis IME macOS 版 v0.1.0（build 1）是第一个版本，以 Cassotis IME 与词库 v1.27.0 为基线：原生 InputMethodKit / AppKit 输入法，配合 Free Pascal 引擎进程、本地 ONNX 推理和简繁词库；全拼、简拼、六种双拼、模糊音、本地学习和 Tab 补全；两行候选窗与八种配色、光标旁的中英文状态气泡、自动保存的设置，以及保留设置和学习记录的签名图形安装器。

Cassotis IME macOS 版 v0.2.0（build 2）移植 v1.29.0：结合上下文的短词重排、长句的文学短语恢复、可选的三行候选展开及跨行鼠标选词，以及只在精确输入时出现的专业词汇。与最小整数的比较和浮点中间结果按 Delphi 的语义改写，使 Apple 芯片上的 Free Pascal 得到相同的候选路径和分数。

Cassotis IME macOS 版 v1.0.0（build 3）移植 v1.31.0：共享的字符语言模型取代 RBT3 短上下文模型，负责长句、带上下文的短词、混合简拼和 Tab 续写；短词补全在后台重排，长句补全比较补完当前词、后续短语和预测的后续字。

Cassotis IME macOS 版 v2.0.0（build 4）移植 v2.2.0，用一个字符语言模型和七个紧凑单元取代 11 个神经网络图。词库外三到五个音节的短语由语言模型组成，并对照输入的拼音修正。新增中文模式下的英文识别、U/I/V 快捷输入、数字后的小数点、Markdown 标点预设和按应用记住的中英文状态；纠错后的分段上屏与撤销保留原始按键，鼻音边界有歧义时单字仍可选择。另加入自定义短语、末音节继续输入时保留补全，以及无上下文短语评分改进。词库在先前 389 个新增项之外，再增加简繁各 67 个回复、集合及仓库用语。
